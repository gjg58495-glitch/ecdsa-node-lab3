# Лабораторная работа 3 — ECDSA Node

Учебный проект демонстрирует безопасную отправку транзакций между аккаунтами с помощью цифровой подписи ECDSA на кривой secp256k1.

## Что реализовано

- React/Vite клиент и Express сервер.
- Публичные ключи используются как адреса аккаунтов.
- Публичный ключ вычисляется на клиенте из приватного ключа.
- Приватный ключ не отправляется на сервер.
- Клиент подписывает транзакцию цифровой подписью ECDSA.
- Сервер проверяет подпись перед изменением балансов.
- **Домашнее задание выполнено:** подпись создается для всех полей транзакции — `sender`, `amount`, `recipient`. Если изменить любое из этих полей после подписания, проверка подписи не пройдет.

## Установка

Требуется Node.js и npm.

### Client

```bash
cd client
npm install
npm run dev
```

Открыть: http://127.0.0.1:5173/

### Server

Во втором терминале:

```bash
cd server
npm install
node index
```

Сервер работает на порту `3042`.

## Тестовые аккаунты

Учебные пары ключей находятся в `client/private/keys.txt`.

> Важно: это демонстрационные ключи. Никогда не храните реальные приватные ключи в открытом виде и не вводите их в обычные веб-формы.

Для создания новой пары ключей после `npm install`:

```bash
cd client
node private/generate.cjs
```

## Как проверить

1. Запустить client и server.
2. В поле **Private Key** вставить приватный ключ аккаунта 1 из `client/private/keys.txt`.
3. Убедиться, что отображается баланс `100` и вычисленный публичный адрес.
4. В поле **Recipient** вставить публичный ключ аккаунта 2.
5. Ввести сумму, например `10`, и нажать **Transfer**.
6. Баланс первого аккаунта уменьшится до `90`, второго — увеличится до `60`.
7. Сервер выведет `Is signed: true`.

## Криптографическая логика

Для подписи формируется один и тот же канонический объект на клиенте и сервере:

```js
JSON.stringify({ sender, amount, recipient })
```

После этого вычисляется `keccak256` от UTF-8 представления строки. Клиент подписывает полученный хэш приватным ключом. Сервер вычисляет тот же хэш и проверяет подпись по публичному ключу отправителя.
